2. For 25,000 elements, the median -O3 times were 118.47 ms for sorted input, 210.82 ms for reverse-sorted input, and 559.06 ms for random input. Using the suggested model, loops and comparisons account for approximately 21.2%, swaps for 8.3%, and the remaining 70.6% is attributed to branch mispredictions. These are rough estimates assuming random input performs about half as many swaps as reverse-sorted input; they do not directly measure each cost.

3. I compiled with -O1 -g -march=haswell and tested 20,000 elements on a Perf-enabled CSIL workstation. Each program called just_sort once, using either RANDOM or SORTED, without warmup. I ran perf stat three times per case and used perf record and perf annotate to locate mispredictions.

4. Random input produced 44,039,274 branch misses, compared with 157,547 for sorted input. Whole-program misprediction rates were 8.78% and 0.0393%, respectively. The sorting if executes 199,990,000 times. Assuming most random-input misses came from this branch gives an estimated misprediction rate of 22.0%. Precise sampling supports this attribution 99.95% of the sampled event weight within bubble_sort was located at its comparison branch. For sorted input, even assigning all program misses to this branch gives only about 0.079%; the actual rate is lower because most sampled misses occurred in stdsort while preparing the input. Thus, the comparison branch was frequently mispredicted for random input and rarely mispredicted for sorted input.

5. For 80,000,000 elements, increasing the height from 1 to 10,000 increased L1 load misses from 21,977,574 to 172,795,408, and LLC load misses from 495,392 to 18,507,540. Average summation time increased from 76.81 ms to 489.15 ms, approximately 6.37×. This matches the expected loss of spatial locality column-wise traversal at height 10,000 accesses elements 64,000 bytes apart. Samples were concentrated near the array-reading instruction in sum_array_col. Perf counts include initialization, and non-precise sampling can shift the recorded instruction location.

6. For 8,000,000 elements, the array-reading line performed 8,000,000 reads in both cases. Increasing the height from 1 to 10,000 increased simulated L1 read misses from 1,000,001 to 8,000,000. Last-level read misses changed from 1,000,001 to 919,635. The L1 results match expectations sequential access reuses a cache line containing eight doubles, while strided access has much poorer L1 locality. Last-level misses did not increase, so the effect was not identical at every cache level. These simulation results use a smaller array and a different cache model from the CSIL hardware experiment.
